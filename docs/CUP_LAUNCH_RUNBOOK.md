## 0. Перед деплоем (локально)

```bash
python scripts/cup_prod_inventory.py --db C:\path\to\server_league.db --rehearse
```

Запускай на **свежем** снапшоте. Скрипт открывает базу только на чтение, репетицию гоняет
на временной копии и копию удаляет. Итог должен быть «готово к запуску». Если у клуба нет
тренера, сначала привяжи клуб через `scripts/bind_clubs_to_players.py` или замени пару в
`scripts/seed_cup_bracket.py::PAIRS`.

## 1. 👤 Деплой

Задеплоить `main` и перезапустить воркер. `init_db()` при старте применит миграции:

- `022_cup_general_stage` — `cup_stages`, колонки этапа у `matches`/`cup_series` и уникальный индекс `(stage, series_num)`;
- `023_cup_topics` — таблица `cup_topics`. Сейчас в ней живут темы «Кубок» (см. шаг 2½);
- `027_division_cups` — `cup_stages.division_id` (кубки дивизионов), `cup_series.announced_winner`,
  уникальность серий переезжает на `(stage_id, series_num)`.

Проверка: бот стартовал, в логах нет ошибок миграций, `/cup` отвечает панелью (пока без этапов).

## 2. 👤 Сид сетки на сервере

```bash
python scripts/seed_cup_bracket.py --stage 1/64
```

Это dry-run: скрипт печатает 16 пар и сезон. Сверь пары с присланным списком.

```bash
python scripts/seed_cup_bracket.py --stage 1/64 --apply
```

Повторный запуск безопасен: если сетка уже есть, сид останавливается.

Проверить цены до открытия ставок (только чтение):

```bash
python scripts/cup_line_preview.py --stage 1/64
```

## 2½. 👤 Тема «Кубок»

Создай в форуме группы тему «Кубок» и отправь **внутри неё**:

```
/set_div_topic общий cup
```

Бот выложит в тему Pillow-сетку кубка и закрепит её. Дальше закреп **редактируется** по мере
результатов; если его удалили или бот не может его отредактировать, сетка публикуется и
закрепляется заново. Кнопка **🖼 сетка в тему** в `/cup` делает то же вручную. Без привязанной
темы кубок молчит — как раньше.

## 3. 👤 Панель `/cup` → этап 1/64

1. **🧩 завести игры** — на каждую серию заводятся заголовок и 3 игры сразу.
2. **🎟 открыть ставки** — открываются `bets_open` и рынки этапа.

Если тема «Кубок» привязана, бот объявляет в ней открытие ставок на этап. Линия живёт в Mini App.

## 4. Проверка в Mini App

В лобби открой чип **🏆 Кубок**. Должно быть:

- этап «1/64 финала» с точкой «ставки открыты» и счётчиком `0/16`;
- на каждой серии «Проход дальше» П1/П2, «Будет ли третья игра» Да/Нет, игры 1–3 с П1/П2/ТБ/ТМ;
- **без ничьей**;
- тестовый купон на 1 серию принимается, и в купоне видно «Кубок · 1/64 финала · серия»;
- экспресс из двух ног **одной** серии отклоняется (`SERIES_CORRELATED`);
- «Сетка» показывает 16 пар со счётом 0:0.

## 5. 👤 Старт этапа

**▶ начать этап**: `is_open = 1`, `bets_open = 0`, рынки этапа закрываются. В Mini App
линия этапа пропадает, остаётся плашка «🔒 Ставки на этап … не принимаются».

Этот же переход открывает **ввод результатов**. Пока идёт приём прогнозов, игры этапа в
«Моих матчах» помечены 🔒, в карточке нет кнопки «📝 Ввести результат», а любое
подтверждение (кабинет, черновик, админ-ввод по фото и вручную) отклоняется с причиной «Этап … ещё
не начат». Результат, внесённый до старта, был бы ставкой на известный исход.

## 6. Результаты серий

Результаты кубковых игр участники сдают боту в ЛС тем же путём, что в лиге: скриншот →
подтверждение. Пост результата уходит в тему «Кубок» **этого** кубка (не в темы лиги), там же —
объявление, кто прошёл дальше (ровно один раз на серию), а закреплённая сетка обновляется. Нет
привязанной темы — бот о результате в группу не пишет.
При равном счёте карточка спросит, кто прошёл дальше (`cup_winner_team`). После второй
победы одной стороны серия закрывается, и **игра 3 аннулируется**, а ставки на неё
возвращаются через `void_market`.

⚠ **Счёт кубковой игры не правь через «админ: изменить счёт»**
(`admin_set_match_score`). Этот путь не двигает серию (известная недоработка, см. ниже).

## 7. Сверка после первой закрытой серии (только чтение)

```sql
-- серия закрыта, победитель проставлен
SELECT id, stage, series_num, team1_name, team2_name, team1_wins, team2_wins, winner_name, status
FROM cup_series WHERE stage = '1/64' ORDER BY series_num;

-- неигранная 3-я игра аннулирована, её рынки закрыты
SELECT m.id, m.game_num_in_series, m.status, mk.status AS market_status
FROM matches m LEFT JOIN markets mk ON mk.match_id = m.id
WHERE m.cup_series_id = ? ORDER BY m.game_num_in_series;

-- ноги на неё вернулись (refund / void), выплаты по сыгранным рассчитаны
SELECT ub.id, ub.status, ub.amount, ub.actual_payout, bi.match_id, bi.outcome_type, bi.status AS leg_status
FROM user_bets ub JOIN bet_items bi ON bi.bet_id = ub.id
JOIN matches m ON m.id = bi.match_id
WHERE m.cup_series_id = ?;
```

## 8. 👤 Итоги этапа

Когда все 16 серий закрыты: сид 1/32 по победителям (1-я серия со 2-й, 3-я с 4-й, …):

```bash
python scripts/seed_cup_bracket.py --stage 1/32 --from-winners
python scripts/seed_cup_bracket.py --stage 1/32 --from-winners --apply
```

Другую жеребьёвку — файлом `--pairs-file pairs.txt` (одна пара «Клуб — Клуб» на строку).
Затем шаги 3–7 повторяются.

## Кубки дивизионов

У каждого дивизиона свой кубок: 16 клубов дивизиона, 1/8 → 1/4 → 1/2 → финал, серии до двух
побед, ставки как в общем, долгов нет. Правят его глобальные админы и админ этого дивизиона —
в `/cup` он видит только свой кубок, глобальный админ переключает кубки кнопками «Общий · Д1 …».
В Mini App переключатель кубков — внутри чипа **🏆 Кубок**.

1. **👤 Тема.** В теме «Кубок Д3» отправь `/set_div_topic 3 cup` (id или код дивизиона) —
   сетка публикуется и закрепляется.
2. **👤 Сид 1/8.** Пары — файлом, одна «Клуб — Клуб» на строку:

   ```bash
   python scripts/seed_cup_bracket.py --division 3 --pairs-file d3.txt
   python scripts/seed_cup_bracket.py --division 3 --pairs-file d3.txt --apply
   ```

   `--division` — id дивизиона (его печатает панель `/cup`) или код `DIV_3`. Скрипт требует
   ровно 8 пар на 1/8 (4, 2, 1 дальше) и только клубы этого дивизиона.
3. **👤 Панель `/cup`** → кубок Д3 → этап 1/8: «завести игры» → «открыть ставки» → «начать этап».
4. **👤 Следующие стадии:** `--division 3 --stage 1/4 --from-winners --apply`, затем 1/2 и `final`.

Превью линии: `python scripts/cup_line_preview.py --division 3 --stage 1/8`.

## Известные ограничения

- Серии уникальны по `(stage_id, series_num)` (миграция `027`): у каждого кубка и сезона свой
  этап, так что кубки не мешают друг другу. Сброс сезона всё равно должен чистить `cup_series`,
  кубковые `matches`, `cup_stages` и `cup_topics`.
- `admin_set_match_score` не двигает кубковую серию: править счёт кубка только через
  подтверждение результата.
- `recompute_cup_series` считает серию до 2 побед жёстко (`>= 2`). Для формата «до 3» это
  место нужно менять.
