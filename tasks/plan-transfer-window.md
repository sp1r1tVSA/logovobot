# План: система трансферного окна

Статус: **согласован, идёт реализация** (этап 1 — база и движок). Ждём от владельца: правила
выдачи бюджетов клубам, полную таблицу доплат OVR → млн, привязку топиков.

Правила прошлого окна (ТГ-пост) даны как иллюстрация механики. Они относятся к прошлым сезонам, где
были лиги, а теперь есть **дивизионы**, поэтому правила окна будут другими (владелец пришлёт позже).
Конкретные числа, запреты и списки живут в настройках окна, а не в коде. Понятия старых лиг
(например, «корзины» клубов для СА) в код не зашиваются: ограничение по клубам задаётся списком в
настройках, а какие клубы туда попадут, определят новые правила. Система не должна предполагать
ни число дивизионов, ни привязку лимитов к ним, пока правила не получены.

## Решения, принятые с владельцем (2026-10-02)

| Вопрос | Решение |
|---|---|
| Что такое трансфер | Тренеры покупают/продают **футболистов** (карточки FC) для состава своего клуба. Смена клуба тренером остаётся админской (`set_player_club`) |
| Окно | Одно на лигу (не по дивизионам). Открывает/закрывает админ вручную **+ дата-время автозакрытия** |
| Бюджет | Привязан к **клубу**, в млн. Выдаётся по правилам, которые владелец пришлёт позже. Остаток после окна сгорает |
| Бюджет без цифр | Система строится без чисел бюджетов: в коде их нет. Правила выдачи владелец даст **до начала окна**, поэтому особого случая «бюджет не задан» нет ни как блокировки, ни как отдельного предупреждения. Открытие окна бюджетов не требует. Клуб без строки в `transfer_club_budgets` считается с бюджетом 0 и получает обычное предупреждение «бюджет превышен». Правила выдачи подключаются одной функцией (`default_budgets`), цифры вносятся таблицей или правкой ответственного |
| Фото трансфера | К заявке можно прикрепить фото (скрин сделки) в Mini App. Хранится как Telegram `file_id`, не на диске (см. ниже) |
| Лимиты | 3 покупки и 3 продажи (настраивается на окно). Слот свободного агента входит в 3 покупки |
| Окно и дивизионы | **Одно окно на лигу** (подтверждено), `division_id` в окне не нужен. Бюджет, лимиты и слоты считаются от клуба |
| Урна | Клуб один раз за окно меняет игрока на деньги: получает **(TM + спешл) / 2**, а для непродаваемой карты **/ 3**. Тратит слот продажи. Подаётся **до старта окна**, одобрение мягкое. Игрока из урны выкупает любой тренер как обычный трансфер («откуда» = «Урна», цена TM + спешл), он занимает слот покупки. Клубы из `urn_restricted_clubs` (в старых правилах «1–2 корзины») урну не используют. Подробно — раздел «Урна» |
| Слоты за монеты | Фиксированная цена в 🪙, максимум докупок на окно задаёт админ. Это наполнение вкладки «🔁 Трансферы» магазина |
| Контрагенты | Сделка между **двумя тренерами**; инициировать может любой из двоих, вторая сторона подтверждает, потом админ. Деньги: покупатель → продавец |
| Свободный агент | **Гонка «на скорость»**: тренеры пишут комментарий под постом ТО в канале, **ответственный передаёт его боту** (пересылка комментария в ЛС бота). Бот разбирает текст, берёт время исходного комментария и фиксирует заявку; игрока получает самый ранний валидный комментарий. Занимает слот покупки и тратит бюджет (цена по ТМ + спешл). **Один на тренера** за окно. Подробно — раздел «Свободные агенты» ниже. Заменяет прежнее решение «только фиксировать, без гонки» |
| Подача | **Mini App** (не слеш-команды). Одобрение — в админ-теме Telegram кнопками ✅/❌ |
| Кто одобряет | **Один ответственный** за трансферы — один Telegram ID в `config.py` (`TRANSFER_MANAGER_ID`) |
| Управление | Окно, бюджеты, применение к составу, санкции — в боте, в ЛС ответственного. Заявки подаются в Mini App |
| Куда идут сообщения | Тренерам лично (ЛС): предложение сделки, подтверждение, решение по их заявке. Остальное — в **одну группу с тремя топиками** (`requests`, `feed`, `alerts`). Топики владелец задаст позже, поэтому их ID не в коде, а в таблице `transfer_topics` (привязка из самой темы, как у `cup_topics`). Пока тема типа не привязана, сообщение этого типа не отправляется (как у кубка без темы) и ответственный видит это в ЛС |
| Проверки | Бот **предупреждает** (бюджет, лимиты, запретные имена), решает ответственный. Бот **запрещает жёстко**: OVR ≥ **114**, правило «5 игроков», второго свободного агента одному тренеру |
| Правило «5 игроков» | После окна в составе клуба остаётся минимум 5 игроков его исходного состава. Считается по `squad_players` |
| Справочник игроков | Накапливается из заявок (имя, клуб на дату, OVR, цена), тренер вводит сам. Героев и кумиров в заявки не подают, типа карты нет |
| Доплата за спешл | Отдельный тип заявки, сумма считается ботом по таблице OVR → млн (100→10 … 111→160), слот не тратит. Бот **сверяет заявленный OVR**: он должен быть выше OVR карты, купленной ранее (по справочнику), и не ниже 100 |
| Состав в базе | Одобренный трансфер правит `squad_players` **по отдельной кнопке** ответственного |
| Висящие заявки при закрытии окна | `pending_manager` остаются до решения ответственного. `pending_counterparty` (вторая сторона не успела подтвердить) **автоматически отклоняется** в момент закрытия |
| Отмена | Тренер может отозвать заявку до одобрения; ответственный может отменить и одобренную (откат бюджета, слотов и состава) |
| История | Да, но **без слеш-команды**: раздел в Mini App |
| Санкции | Лишение окна на N сезонов ставит ответственный кнопкой; бот не принимает заявки клуба/тренера под санкцией |

## Модель данных (миграция `033_transfer_window`, только аддитивно)

- Деньги хранятся целыми в тысячах (`price_k`, `budget_k`, 12.5 млн = 12500), чтобы не было ошибок
  с дробными. Деление на 2 и 3 для урны округляется вниз до 100 тыс. (допущение, см. ниже).
- `transfer_windows` — `id`, `status` (`draft|open|closed`; одновременно не больше одного окна не в `closed`), `opened_at/by`, `auto_close_at`, `closed_at/by`,
  `season_id`, настройки окна: `max_buys`, `max_sells`, `max_extra_slots`, `slot_price_coins`,
  `ovr_cap` (114), `min_core_players` (5). Одновременно открыто не больше одного.
- `transfer_club_budgets` — `(window_id, club_name) → budget_k`, `source` (правило/ручная правка).
- `transfers` — заявка: `window_id`, `kind` (`deal|free_agent|surcharge|urn_sale|urn_buy`), для урны ещё `tm_price_k`, `special_price_k`,
  `sellable`, `urn_item_id` (у `urn_buy` ссылка на `urn_sale`), игрок (имя + `norm_name`),
  `from_club`/`to_club` (клуб турнира или текст «вне турнира»), `from_user`/`to_user`, `price_k`, `ovr`,
  `photo_file_id` (nullable), `source_text` / `commented_at` / `reported_budget_k` (для СА), `initiator_id`, `status`
  (`pending_counterparty|pending_manager|approved|rejected|withdrawn|cancelled`),
  `warnings` (JSON), решение (`decided_by/at/reason`), `squad_applied_at`, `created_at`.
- `transfer_squad_ops` — что именно изменено в `squad_players` (для отката).
- `transfer_core_snapshot` — исходный состав клуба на момент открытия окна (основа правила «5 игроков»).
- `transfer_players` — справочник, накапливаемый из заявок (имя, клуб на дату, OVR, цена) + флаг
  `banned`: необязательный список запретных имён, который ведёт ответственный. Героев и кумиров
  в заявки не подают, поэтому типа карты в модели нет и проверки на него нет.
- `transfer_topics` — `(topic_type, group_chat_id, message_thread_id)`, уникально по `topic_type`; все
  топики в одной группе. Типы (предложение, владелец может сократить): `requests` — карточки заявок с
  кнопками ✅/❌ и фото; `feed` — публикации одобренного, отклонённого, открытие и закрытие окна;
  `alerts` — предупреждения бота, автоотклонения, ошибки доставки. Привязка — командой внутри
  нужной темы ответственным (тема сама сообщает свой `message_thread_id`).
- `transfer_slot_purchases` — докупленные слоты за 🪙 (`window_id`, клуб, тип, цена, `coin_tx_id`).
- `transfer_sanctions` — клуб/тренер, до какого сезона, причина, кто поставил.

**Принцип как в «Сверке с матчами»:** остаток бюджета и занятые слоты **не хранятся**, а считаются
при чтении из заявок и покупок. Отмена одобренного трансфера не требует ручного отката счётчиков.
Занятыми считаются слоты и бюджет по заявкам `pending_*` и `approved`, чтобы нельзя было
завалить очередь заявками сверх лимита.

Все времена MSK (`time_utils`, `datetime('now', '+3 hours')`), SQL параметризованный, всё через
`database.transaction()`. **Отступление от CLAUDE.md:** SQL пакета лежит в `transfers/repo.py`, а не в
`database.py` (требование «отдельная папка»). Подключения и транзакции берутся из `database.py`, а не
открываются заново. После согласования правило в `CLAUDE.md` дополнится оговоркой про `transfers/`.

## Структура кода: отдельный пакет `transfers/`

Вся система живёт в одной папке, в существующие файлы вносятся только тонкие точки подключения.

```
transfers/
  __init__.py      # публичный вход: register_handlers, register_jobs, register_routes, apply_schema
  engine.py        # чистые функции проверок и расчётов, без БД и Telegram
  schema.py        # миграция 033: CREATE TABLE IF NOT EXISTS + запись в schema_migrations
  repo.py          # SQL пакета (через database.transaction / get_connection)
  service.py       # сценарии: окно, заявка, подтверждение, одобрение, состав, слоты за 🪙
  api.py           # aiohttp-маршруты Mini App (/api/transfers/...)
  handlers.py      # Telegram: ЛС ответственного, кнопки в админ-теме
  jobs.py          # автозакрытие окна
  config.py        # таблица доплат, значения по умолчанию (env читается в корневом config.py)
  web/             # transfers.js, transfers.css, фрагмент разметки
```

Точки подключения в остальном коде (по одной строке): `database.init_db()` → `transfers.apply_schema`,
`handlers/__init__.py` → `transfers.register_handlers` **до** AI-catch-all, `main.register_jobs` →
`transfers.register_jobs` через `_run_repeating`, `api/server.py` → `transfers.register_routes`,
`web/index.html` и `web/js/app.js` → подключение вкладки. Тесты лежат в `tests/`
(`pytest.ini` берёт только `tests`), файлы с префиксом `test_transfer_`.

## Свободные агенты (СА): передача данных через ответственного

Правила прошлого окна (могут поменяться, поэтому всё в настройках окна): игрок из клуба, которого нет
в турнире; один СА на тренера; комментарий формата «1. Имя Фамилия (латиницей, целиком) / 2. Откуда
(полное название клуба) / 3. Куда (полное название клуба) / 4. Сумма в млн (цена по ТМ + спешл) /
5. Остаток бюджета / 6. Фото (необязательно)»; один игрок — один комментарий; правка комментария
аннулирует трансфер; трансферы засчитываются с заданного момента (20:00 МСК); запрещены бесхозные
клубы АПЛ из списка, герои и кумиры, завершившие карьеру, карты OVR 112+; клубы 1–2 корзин СА не
берут. Игрока получает тот, кто написал **раньше**.

**Как данные попадают в бота.** Бот комментарии канала не читает. Ответственный **пересылает**
комментарий боту в ЛС. У пересланного сообщения есть исходное время и текст, оно и есть момент
«гонки», а не время пересылки. Бот:
1. Разбирает 5–6 пунктов детерминированно (нумерация строк, регулярки), без ИИ. «Куда» приводит к
   клубу через `club_registry.resolve_team_name_ex`, по клубу находит тренера (отправитель
   комментария для этого не нужен, у пересланного он может быть скрыт). «Откуда» хранится текстом.
2. Проверяет и показывает ответственному карточку с результатом: распознанные поля, предупреждения
   и кнопки ✅ Записать / ✏️ Исправить / ❌ Отклонить.
3. Предупреждает (решает ответственный): комментарий раньше `fa_opens_at`; клуб «Откуда» в списке
   запрещённых; клуб «Куда» в списке ограниченных клубов `fa_restricted_clubs` (задаёт ответственный); у тренера уже есть СА;
   игрок уже записан за другим (показывает, чей комментарий раньше); указанный остаток бюджета
   не совпал с расчётным; имя не латиницей или без фамилии; бюджета не хватает; лимит покупок.
4. Если игрока уже записали, а пересланный комментарий **старше**, бот предлагает передать игрока
   более раннему (старая запись отменяется, слот и бюджет освобождаются), решает ответственный.
5. После ✅ запись `transfers(kind='free_agent', status='approved')` с `source_text`, `commented_at`,
   `reported_budget_k`, сообщение в тему `feed`, ЛС тренеру.

Порядок пересылки не важен: приоритет считается по `commented_at`. Тренер сам СА в Mini App не
подаёт, но видит его в истории. Настройки окна: `fa_opens_at`, `fa_forbidden_clubs`,
`fa_restricted_clubs`, `fa_ovr_cap` (112, у обычных сделок остаётся `ovr_cap`). В комментарии OVR
нет, поэтому бот его не проверяет: ответственный вносит OVR при записи (поле необязательное).
Если позже понадобится, бота можно добавить в группу обсуждения канала, тогда комментарии
будут приходить без пересылки.

## Урна

Игрок, которого никто не покупает (неизвестный или «рейтинговая карта, плохие статы»), уходит из
клуба за деньги по сниженной цене. Известных игроков в урну сливать нельзя, это проверяет
ответственный глазами, поэтому одобрение мягкое (одна кнопка, без обязательных проверок бота).

**Продажа в урну (`kind = urn_sale`).** Форма Mini App: игрок, фото (необязательно), откуда ушёл
(клуб тренера), цена за спешл, цена по Transfermarkt, переключатель «карта непродаваемая». Общую
цену тренер не вводит: бот считает `urn_payout(tm, special, sellable)` = `(tm + special) / 2`, для
непродаваемой `/ 3`, делители лежат в настройках окна. Одна урна на клуб за окно, считается как
слот продажи. Клубы из `urn_restricted_clubs` получают отказ. Предупреждения (решает ответственный):
игрока нет в `squad_players` клуба, лимит продаж исчерпан, игрок похож на известного (по справочнику:
был в сделках, OVR высокий).

**Выкуп из урны (`kind = urn_buy`).** Обычная заявка на трансфер, где «откуда» = «Урна», а
`urn_item_id` указывает на запись `urn_sale`. Цена = TM + спешл полностью. Подтверждения второй
стороны нет (продавец уже получил свою половину), заявка сразу уходит ответственному. Слот покупки
тратится, бюджет покупателя уменьшается. Клубы из `urn_restricted_clubs` выкупать не могут. Один
игрок в урне выкупается один раз: пока есть `urn_buy` в `pending_*`/`approved`, игрок занят.

**Когда.** Продавать в урну можно до старта окна. Для этого у окна появляется статус `draft`
(заявки в урну принимаются, обычные сделки и СА нет), затем `open`, затем `closed`. Кошелёк клуба
после одобрения продажи в урну пополняется, остаток считается при чтении. Игроки, которых никто не
выкупил, остаются в урне до закрытия окна, потом пропадают.

**Что видят тренеры.** В Mini App вкладка «Урна»: список доступных игроков (имя, откуда ушёл, цена
выкупа), от неё кнопка «Выкупить». Игрок уходит из `squad_players` продавца кнопкой ответственного,
как и в обычной сделке, а в состав покупателя попадает при выкупе.

## Сервисы и слой API

- `transfers/engine.py` — **чистые функции**, без БД: `evaluate_request(...)` →
  список предупреждений (бюджет, лимиты, запретное имя, санкция) + жёсткие блокировки
  (OVR ≥ 114, правило «5 игроков», второй свободный агент); `surcharge_cost(ovr)`; расчёт остатков.
- **Фото заявки.** Mini App шлёт `multipart` в `transfers/api.py`; сервер ограничивает размер и
  тип (JPEG/PNG/HEIC, проверка через Pillow), перекодирует, отправляет фото в админ-тему как часть
  карточки заявки и сохраняет `file_id`. Диск не нужен. Показ в истории идёт через маршрут-прокси
  `getFile` (как в `routes_matches.py`), токен остаётся на сервере. Фото необязательно, по
  правилам окна его можно сделать обязательным для сделок.
- Корневой `config.py` — только `TRANSFER_MANAGER_ID` (env читается там); таблица доплат за спешл и
  цена слота по умолчанию — в `transfers/config.py`.
- `transfers/api.py` — окно/мой клуб/создать/подтвердить/отозвать/история.
- `transfers/web/transfers.js` + секция в `index.html` — Mini App: статус окна, бюджет и слоты клуба,
  форма заявки, входящие предложения, история. Покупка слотов — вкладка «Трансферы» магазина.
- Бот: админ-тема для заявок (кнопки ✅/❌/«применить к составу»/«отменить»), тема «Трансферы» для
  публикаций, управление окном и бюджетами у ответственного, `register_jobs()` — автозакрытие окна
  через `_run_repeating`, чтобы `/health` видел джоб.
- Журнал: все решения через `admin_journal.record` + строки в `ACTIONS`.

## Подтверждено владельцем

- Подменять ответственного нельзя никому: действует только `TRANSFER_MANAGER_ID`. Если ID
  недоступен, заявки ждут. Аварийного доступа не будет.
- Панелью `/to` (окно, бюджеты, автозакрытие, темы) ещё могут пользоваться админы из `ADMIN_IDS`.
  Уведомления «ответственному» идут только `TRANSFER_MANAGER_ID`.
- Автоотклонение при закрытии окна касается только `pending_counterparty`. Заявки, уже ушедшие
  ответственному, он решает после закрытия.
- В форме заявки Mini App есть переключатель **«Спешл»**. Включённый, он превращает заявку в
  доплату за спешл (`kind = surcharge`): вместо второго тренера и цены поля «игрок» и «новый OVR»,
  сумму ставит бот по таблице, слот не тратится, одобряет ответственный.

- Доплата за спешл списывается из бюджета клуба. СА тоже тратит бюджет (цена по ТМ + спешл).
- Урна: цена округляется вниз до 0.1 млн, если деление на 2 или 3 даёт дробь; продажа в урну
  подаётся в Mini App. Правила урны, как и остальные правила, служат только иллюстрацией механики,
  делители и ограничения лежат в настройках окна.
- Фото в заявке необязательно. Историю трансферов в Mini App видят все тренеры лиги (общая лента
  одобренных + свои заявки с любым статусом).

## Допущения, которые стоит подтвердить

- Настройки урны (`urn_divisor_sellable` = 2, `urn_divisor_unsellable` = 3, `urn_max_per_club` = 1,
  `urn_restricted_clubs`) лежат в настройках окна и меняются без правки кода.

- Сверка OVR для доплаты идёт по справочнику заявок. Если игрока в справочнике нет, доплата
  не блокируется, а получает предупреждение «нет данных о прежней карте».
